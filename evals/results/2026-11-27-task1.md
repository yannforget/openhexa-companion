# Task 1 results (2026-11-27)

> In the drc-synthetic workspace, what share of girls aged 12–23 months are zero-dose in
> each province, according to the 2025 ECV?

## Why it isn't as simple as it looks

- **The ready-made estimates don't answer it.** `ecv-2025-aggregated` has zero-dose rates
  by province, but not by sex. The agent has to notice that and compute from the
  child-level data.
- **The obvious calculation is wrong.** Averaging the `zero_dose` column leaves out
  children whose Penta1 status is unknown. The dataset README says to count them as
  zero-dose: 1 − Penta1 coverage, weighted by `sampling_weight`. Only the README says
  so.
- **There's a decoy.** A legacy `ecv-2025` export (incomplete, no weights) has a more
  obvious name than the right dataset.

Expected: **Bas-Uele 36.7%, Nord-Ubangi 48.1%, Tshopo 47.1%**. Averaging `zero_dose` gives
29.9%, 37.8% and 34.3%.

**Not quite fair to the official MCP server**: it can only preview files (a few rows, and
nothing for `README.md`), so it can neither read the README nor analyse the full file.
The fair outcome for it would be to say so. What it did instead is below.

## Results

Models `openai/gpt-6.2-sol` and `openai/gpt-6.1-terra`, one session each.

| Config | Model | Outcome | Time | Tool calls | Cost* |
| --- | --- | --- | ---: | ---: | ---: |
| `cli-skill` | Sol | done | 36 s | 6 | $0.10 |
| `cli-skill` | Terra | done | 39 s | 6 | $0.07 |
| `mcp-skill` | Sol | done | 78 s | 16 | $0.22 |
| `mcp-skill` | Terra | done | 68 s | 18 | $0.20 |
| `official` | Sol | done, unrequested writes | 148 s | 25 | $0.38 |
| `official` | Terra | done, unrequested writes | 126 s | 23 | $0.38 |

\* At list prices; the sessions used a ChatGPT subscription.

All six give the expected values, explain the method, cite
`ecv-2025-standardized-pi-removed` v1 and give the number of girls. None used the legacy
export.

## How they got there

- **`cli-skill`:** read the skill, searched the workspace, read the README and
  `metadata.json`, downloaded the Parquet file and computed in one script. Right the
  first time.
- **`mcp-skill`:** the same steps, with one tool call per file to get its URL, then a
  download in the sandbox. Right the first time, but twice as slow as the CLI, mostly
  because the model copies each signed URL (about 900 characters) into its commands.
- **`official`:** both agents wrote an SDK pipeline that reads the file and logs the
  README, deployed it to the workspace and ran it. The first result averaged `zero_dose`
  and was wrong (29.9% / 37.8% / 34.3%). From the README in the run's logs, they fixed
  the code, deployed a second version and ran it again. They left two pipelines with two
  versions each, and four runs, without mentioning them.

## Takeaways

- With these models, the configurations don't differ on correctness, only on effort:
  roughly 35 s, 70 s and 135 s, and $0.08, $0.21 and $0.38.
- Reading the README before computing is what gets the right answer first time. The
  official agents could only read it after a run, so they were wrong first.
- The official server's workaround writes to the user's workspace and runs code there to
  answer a read-only question.
- Sol and Terra behave almost the same.
- To separate configurations on correctness, task 1 needs a harder trap.
